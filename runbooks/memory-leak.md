# Runbook: 内存泄漏排查

## 适用场景

服务内存持续增长不回落，最终 OOMKilled 或被 OOM Killer 杀进程。

## 步骤

1. 查监控：观察内存使用曲线，确认是"持续爬升"还是"阶梯式上涨"，定位泄漏节奏。
2. 查进程：`top` / Heap dump，确认是堆内（Java/Go 对象）还是堆外（缓存、连接、线程栈）。
3. 若为堆内泄漏：抓 heap dump，对比两个时间点的存活对象，找只增不减的类型。
4. 若为堆外：重点查本地缓存、线程池/连接池未释放、DirectMemory（Netty 常见）。
5. 定位后验证：修复版本上线后，观察内存曲线在稳定区间不再爬升。

## 经验

缓存类组件（Redis 客户端、连接池）最常被误配成无上限；上线前先确认 maxTotal/maxEntries 有界。
