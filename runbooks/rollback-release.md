# Runbook: 版本回归回滚

## 适用场景

发布后出现功能异常、错误率上升或性能下降，怀疑为最近发布引入的版本回归。

## 步骤

1. 确认故障时间与最近发布窗口重合：对比故障开始时间与上线时间。
2. 核对变更内容：查看本次发布涉及的代码/配置/依赖变更，锁定可疑改动。
3. 回滚策略：
   - 镜像回滚：切回上一个已知良好镜像标签。
   - 配置回滚：恢复上一版配置（注意 ConfigMap/环境变量一并回滚）。
4. 灰度验证：先回滚少量实例，确认指标恢复再全量。
5. 复盘：回滚后仍要定位根因并修复，避免"回滚即了事"。

## 注意

回滚不是根因分析的终点；保留回滚前现场（日志、指标快照），供后续定位。
